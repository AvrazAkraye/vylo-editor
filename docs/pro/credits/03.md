# Credits: 03 MP4 with sound

**No code was copied or closely translated** from HyperFrames or anywhere else, so no file carries an
Apache-2.0 header. Everything in `motionaudioenc.ts`, the sound track in `motionmp4.ts`, and
`changingFrames` in `motionexportops.ts` was written here from the standards below and from measurement.

## Ideas taken, with thanks

- **HyperFrames** (heygen-com/hyperframes, Apache-2.0), as digested in `docs/pro/RESEARCH.md`:
  - that AAC's encoder delay belongs in the MP4 edit list (`elst`) so sound and picture start together;
  - that the picture should be tagged with a `colr` box (`engine/src/utils/sdrCaptureColor.ts`; Motion
    already wrote one, with a measured sRGB transfer, and keeps it);
  - `computeStaticFrameSet`: repeating the previous encoded frame instead of painting it again. HyperFrames
    has to infer stillness from GSAP; here it is read exactly from the document.
- **mediabunny** (MPL-2.0, present in `node_modules` as a dependency of Remotion's web renderer, which Video
  uses): reading its source taught that WebKit's AAC `description` is malformed (WebKit bug 302253) and that a
  missing description means ADTS. Nothing was copied; Motion does not import it.
- **ffmpeg** and **Apple's AAC writer** (`afconvert`): their files were inspected byte by byte (box structure
  only) to learn the `sgpd`/`sbgp` roll group AVFoundation needs. ffmpeg is used only by the tests, where it
  is installed, as an independent decoder.

## Standards followed

ISO/IEC 14496-12 (ISO base media file format: `trak`, `elst`, `mp4a`, `sgpd`/`sbgp`), 14496-14 (MP4:
`esds`), 14496-1 (descriptors), 14496-3 (AudioSpecificConfig, ADTS), the WebCodecs specification, and ITU-R
BT.1359 (why sound a little late is the safer error).
