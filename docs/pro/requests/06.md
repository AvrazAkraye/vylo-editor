# Requests from 06 Gallery and brand kit

Changes outside this package's files that the integrator should make. Each is small; the first two are what make the
brand kit do what it says.

## 1. New graphics start in the kit (`MotionPanel.tsx`)

`startTemplate` builds through the kit, and the panel loads the kit once so the sidebar's template list (which does
not mount Home) knows it too:

```ts
import { kitOptionsWithBrand } from './motionbrand';
import { currentBrand, loadBrand } from './motionstore';

// once, where the panel loads the graphics (the `loaded` effect):
void loadBrand();

// startTemplate:
const built = buildMotion(kitOptionsWithBrand({ id: newId(), recipe: id, lang, format: o.format, palette: o.palette, request: '' }, currentBrand()));
```

`o.palette` is `undefined` when the person chose Auto, so the kit's palette applies; a palette they picked wins.

## 2. A rebuild keeps the brand's face and logo (`motionedit.ts`, `motionchatops.ts`)

Changing a template graphic's words, shape, language or length builds it again without its look, so a branded graphic
loses its face and logo (its palette and words are kept). One argument each:

```ts
// motionedit.ts, rebuild():
import { buildMotion, lookOf } from './motiontemplates';
const fresh = buildMotion({ ...same as now..., look: lookOf(m) });

// motionchatops.ts, rebuilt(d, recipe, fields, now): keep the look when the template is the same one
look: d.recipe?.id === recipe ? lookOf(d) : null,
```

`lookOf` builds the template once more, plainly, to compare faces id by id (well under the 50 ms the fuzz allows a
build); it returns null for a graphic with no look, so unbranded graphics rebuild exactly as now.

## 3. Mount the button in Design (`MotionDesign.tsx`)

One line, at the top of the Colours section (or beside the section title):

```tsx
<MotionBrandKit t={t} doc={doc} onChange={(next) => onEdit(() => next)} />
```

The sheet then offers "Apply to this graphic" beside Save. Home already mounts its own (no `doc`).

## 4. Words do what buttons do (wave 2, chat)

A `brand.apply` op is `applyBrand(d, currentBrand(), run.now)`; it returns `d` itself when there is no kit or nothing
to change. Package 10's new-graphic path (`motionai.ts`, a template picked by the model) can build through
`kitOptionsWithBrand` the same way as `startTemplate`; whether a palette the model chose should beat the kit's is a
product decision (the kit's seems right unless the person named colours).

## 5. For packages 07 and 08 (their metadata files)

- A field that means the brand gets `brand: 'name' | 'handle' | 'url' | 'initials'` (`Field.brand` in
  `motionrecipe.ts`). A person's name (a lower third) must not. `url` has no user among the original eighteen: an end
  card or a price card's website line would be the first.
- A template with a natural place for a logo gets `logo: { layer: '<the layer it replaces>', drop: [<layers that only
  made sense without it>] }` (see the logo reveal in `CORE_META`).
- Search finds their templates by their tags, names, descriptions, field labels and `useWhen` with no change. Words of
  their own in Arabic, Sorani and Badini can be added to `LOCAL_WORDS` in `motionsearch.ts`.

## 6. Seen while working, not this package's (for 04 and 05)

`motionedit.ts`'s `rebuild` returns `{ ...fresh, title, fps, backdrop, stage, error, created, updated }`, and `fresh`
comes from `buildMotion`, so **any rebuild drops `Motion.sound` and `Motion.scenes`** (new words in a template graphic
with sound lose the sound). `applyBrand` avoids this by spreading the graphic and replacing only what it changes.
