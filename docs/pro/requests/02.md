# Requests from work package 02 (audio library)

Things outside 02's files that the integrator should do. None blocks 02's own tests.

1. **THIRD_PARTY_NOTICES.md** (the Wave 2 refresh): `app/src/audioauto.ts` contains code derived
   from HyperFrames (`heygen-com/hyperframes`, Apache-2.0), `packages/core/src/audioAutomation.ts`
   and `packages/core/src/audio/audioFxAutomation.ts`. The file carries the header; the notices
   file needs the entry and the licence text. Details in `docs/pro/credits/02.md`.

2. **Package 04 (sound design) and anyone calling `loudness.ts`:** the names and signatures are
   unchanged, and `Loudness` is still exactly `{ lufs, peakDb }`, but **`peakDb` now means the
   true peak** (4x oversampled), which is up to 3 dB over the sample peak for a bright sound. A
   test of 04's that hard-codes the placeholder's RMS-based numbers will read differently; a
   static gain from `gainToTarget` is now held under the true peak, as delivery requires.
   `measureLoudness` returns `LoudnessReport` (adds `truePeakDb`, `samplePeakDb`, `range`).

3. **Package 03 (MP4 with sound):** to deliver at -16 LUFS under -1.5 dBTP, a bed can go
   `normalizeLoudness(bed, rate)` and then `renderChain(…, [{ type: 'limiter', ceiling: -1.5 }])`
   (true-peak limiting is on by default); `resample(ch, from, to)` if the bed's rate is not the
   encoder's. AAC encoding can add its own overshoot of a few tenths of a dB on top.

4. **The WebKit audio check** (optional, a script outside 02's lane): 02 measured its builders in
   the app's WKWebView with a host kept in the git-ignored `app/.test-build/audio-harness/`
   (`webkit-host.swift`, `check.ts`, `run.mjs`; see docs/pro/audio.md). If the project wants it
   kept, it belongs under `scripts/` with the Motion harness. It needs the sandbox off for
   WebKit's helper processes and loads its page with `loadHTMLString`, because a page served over
   loopback never committed in this session.

5. **Wave 2 wiring** (no UI in 02): the Sound row's preview can play a rendered bed directly
   (preview equals export trivially), or build `buildChain` with `chainEnvelopes` for an exact
   live chain; a music bed under a voice gets `duckLane` and `compile` on its GainNode.
