# Requests from 09 Export and sharing

Changes outside package 09's files that its work needs. Most important first.

**Status, wave 2 (W2-2, branch `pro-w2-export`):** 1, 2, 3 and 5 are done. Rust saves a `.gif` (it must begin
`GIF89a` or `GIF87a`; 64 MiB; opened by Open), SAFETY.md says so in all four languages, `fileNameFor` takes `'gif'`,
`seeThrough` is exported from `motionexportops.ts`, the tab's `renderMp4` call carries the sound, and docs/MOTION.md
lists GIF and the new files. Left for 09's files (not changed by W2-2): `motionshare.ts`'s `fileNameOf` can call

(`test/pro-export.test.mjs` holds the two equal meanwhile). 4 is W2-1's (`motionedit.ts`), 6 is W2-3's (chat).

## 1. Rust must accept a GIF (blocking: without it no GIF can be saved)

`app/src-tauri/src/video.rs` (`export_write_video`, `open_exported`) writes only `.mp4 .webm .png
.srt .json`. Download GIF and Save as… GIF reach it with `Title 16x9.gif` and bytes starting `GIF89a`,
and today it refuses them ("is not a file the Video panel saves"); the tab shows that as a sentence.

- Add `Kind::Gif` for the extension `gif`.
- `check`: the bytes start with `GIF89a` (the writer only writes 89a; accepting `GIF87a` too is harmless).
- `cap`: `MAX_IMAGE_BYTES` (64 MiB). The tab keeps a GIF under 25 MB and saves one still over only at
  the bottom of its ladder (240 px, 6 a second, 64 colours, at most 15 s), which is far below 64 MiB.
- `openable`: yes (a GIF opens in Preview or the browser).
- Tests: add `("loop.gif", gif())` to `export_write_video_writes_each_kind_it_saves`, a `gif.gif` that
  is a PNG to the wrong-bytes refusals, and keep `x.webp`/`x.jpg` refused.
- The module header table gains a row: `.gif` | a looping animation | `GIF89a` | 64 MiB.

## 2. SAFETY.md, in all four languages, says which files are written

`SAFETY.md` (and `.ar`, `.ckb`, `.kmr`), the `export_write_video` and `open_exported` bullets, list
".mp4, .webm, .png, .srt and .json" and say the Motion panel writes "an MP4 or a PNG". With request 1
they become: Motion writes "an MP4, a GIF or a PNG"; the refused-names list gains `.gif` as accepted;
"a GIF without its `GIF89a` signature" joins the wrong-bytes examples; `open_exported` opens a `.gif`
too. The remembered-choices sentence (`vylo.motion.export.v1`) stays true as written: the same key now
also keeps the GIF's size and rate. This changes a SAFETY claim (PRO.md, rule 7 says SAFETY's claims
are unchanged), so it is the owner's call; the honest alternative is to hide the Web loop card and
Custom's GIF until it is made.

## 3. `motionexportops.ts` (package 03's file)

- `fileNameFor(m, ext: 'mp4' | 'png', tag)`: widen `ext` to include `'gif'`. `motionshare.ts`'s
  `fileNameOf` then calls it directly instead of naming a PNG and swapping the extension.
- Export `seeThrough` (or move it to `motiontypes.ts`): `motiongifops.ts` has a copy of the rule.
- The header's "Motion adds no command and no kind of file: an MP4 and a PNG" becomes "an MP4, a GIF
  and a PNG", and its list of what Rust writes gains `.gif`.
- When `renderMp4` gains its sound option, the one call in `MotionExport.tsx`'s `start()` needs it, and
  `RenderDeps.paint` must stay injectable: a graphic fitted into another shape is painted through it
  (`fittedPaint`).

## 4. `motionedit.ts`: building a template again for a new shape drops its sound

`rebuild` (used by `setFormat`, `setLang`, `setSeconds`, `setFields`) returns `buildMotion`'s graphic
plus title, fps, backdrop, stage and dates; `sound` (package 04) and `scenes` (package 05) are lost. In
Export this is worked around (`outputOf` carries `sound` back; a graphic with scenes is fitted, not
rebuilt), but the Design tab's shape, language, length and word edits will lose a template graphic's
sound. Suggest `rebuild` keeps `sound` (and decides what `scenes` mean after a rebuild).
