# Requests from 03 (MP4 with sound)

Changes package 03 needs in files it does not own. None blocks the package: everything here is wiring for
wave 2. Details and the API are in `docs/pro/mux-audio.md`.

## 09 `MotionExport.tsx` (or the integrator)

- Pass `sound: true` to `renderMp4` when the graphic has sound (04's `doc.sound`, mode other than `'off'`).
  Off by default keeps the shortest path unchanged.
- The result is still the bytes for `writeMotionFile`, now carrying `audio`. When `audio === 'dropped'`, say so
  once, quietly, after the save ("Saved without sound: this window cannot encode it." or similar, through
  `t()`, with `ar`/`ckb`/`kmr`). Never an error: the film is good.
- Optional: while `onSound` runs (before the first frame), the bar has no frames yet; a "Preparing sound" label
  would read better than the early state. `onSound(done, total)` gives a fraction.

## 05 `motionscene.ts`

- A document with scenes is painted at every frame (`changingFrames` cannot know when scene time moves). If
  `motionscene.ts` exported the moments its scenes and transitions are under way (for example a
  `sceneMotion(doc): [from, to][]`), 03's plan could skip the holds inside scenes too. Not needed for
  correctness.

## 08 (new charts and backdrops)

- A chart type other than `bars`, `hbars`, `line`, `donut`, `ring`, and any new kind of layer, is painted at
  every frame it shows (`STILL_CHARTS` / `STILL_KINDS` in `motionexportops.ts`, 03's file). A new chart that is
  drawn only from its pose (no time of its own between its entrance and exit) can be added to that list after
  merging; a bar-chart race must not be. New backdrops need nothing (backdrops always count as moving).

## Integrator

- `docs/MOTION.md`: remove "Sound" from "Not in this version"; add `motionaudioenc.ts` to the engine table
  ("a graphic's sound as AAC, with WebCodecs"); `motionmp4.ts` writes "the picture and the sound"; one line
  that frames which cannot have changed are encoded again without being painted.
- After merging, run `node test/pro-mux-audio.test.mjs`: its template sweep compares the skip plan with full
  renders of every recipe in `RECIPE_IDS`, including 07's and 08's. A failure there means a template draws
  something time-dependent the plan does not know; the fix belongs in `changingFrames`.
- The real-engine harness used for this package lives in `app/.test-build/mux-harness/` of the
  `vylo-editor-pro-03-mux-audio` worktree (git-ignored): `run.mjs [chrome|webkit|both]` exports films with
  sound in both engines and checks them with ffprobe, ffmpeg and AVFoundation; `skip.ts`'s `skipProof` hashes
  every frame's pixels to prove skipped frames identical.
