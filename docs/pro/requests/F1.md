# F1 (a template owns a span): requests to the integrator

Changes outside F1's files that its new rule needs. The rule and its reasons are in `docs/pro/f1-until.md`.

## 1. "Apply to this graphic" must re-skin only the template's part (motionbrand.ts) — important

**What a person would see.** Big title, "+ Scene", a text in the new scene, then Brand kit → "Apply to this graphic":
`applyBrand` builds the template for the whole graphic (`seconds: doc.seconds`) and replaces every layer, so the title
is laid across both scenes again and the text in the second scene is gone; the link loses its `until`. (Before F1 the
graphic had stopped being a template at "+ Scene", so this path recoloured it by hand instead.)

**Fix**, one line at the top of `applyBrand`, after the kit is read (motionbrand.ts already imports from motionedit.ts):

```ts
import { onTemplatePart, setLayer, setPalette } from './motionedit';
…
  const kit = brand ? readBrand(brand) : null;
  if (!kit) return doc;
  if (doc.recipe?.until !== undefined) return onTemplatePart(doc, (part) => applyBrand(part, kit, now));
```

`onTemplatePart` hands `applyBrand` the template's part as a graphic of its own (no span, so the recursion runs the
existing template branch once) and puts the result back: the template re-skinned, the person's scenes and layers, the
length, scenes and sound as they were; the very `doc` when nothing changed. The chat's `brand.apply` already does
exactly this (motionchatops.ts), and `test/pro-until.test.mjs` checks the two agree; with the line above the chat's
wrapper becomes redundant but stays correct. A test to add with it (pro-gallery or pro-until):
`applyBrand(addLayer(addScene(bigTitle, 1), 'text', { id: 'mine' }, now, 7.5).motion, kit)` keeps `mine` and
`recipe.until === 6`.

## 2. docs/pro/scenes.md's edit table (package 05's page)

The table's "template link" column says `addScene` and `moveScene` drop it. Now: `addScene` keeps it when the cut is
at or after the end of the template's part (setting `recipe.until`) and drops it inside; `moveScene` keeps it when the
move is among the scenes after the template's part. One line each, pointing at `docs/pro/f1-until.md`.

## 3. docs/MOTION.md, once F2 is merged

If MOTION.md describes "+ Scene" or editing by hand as ending the template, add the exception: scenes added after a
template's end are the person's, and the template's words stay editable in Design. (F2 owns MOTION.md in this wave.)
