# Requests from review R1 (safety, readers and the promises)

Changes outside the files this review may edit (`motionread.ts`, `motionscene.ts`, `motionsound.ts`,
`motionbrand.ts`, `motionchatops.ts`, `motionsearch.ts`, `motionshare.ts`, `motioncheck.ts` and their tests). The
findings behind each are in `docs/pro/review-safety.md`; `test/pro-review-safety.test.mjs` is where each one, once
done, gets its test. Ordered by what they protect.

## 1. The audio library's readers must not throw or walk holes (`audioauto.ts`, `audiofx.ts`, `audioduck.ts`)

Nothing in the app feeds these readers outside data yet (only `test/pro-audio.test.mjs` imports them), which is why
this is a request and not a fix. The headers promise "never throws", and today:

| reader | a Proxy whose traps throw | a revoked Proxy | an object whose getters throw |
|---|---|---|---|
| `readAutomation` | throws | throws | throws |
| `readLane` | throws | throws | throws |
| `readFx` | throws | throws | ok |
| `readChain` | ok | throws | ok |
| `readDuck` | throws | throws | ok |

- `record()` in `audioauto.ts` calls `Array.isArray` outside a try (a revoked Proxy throws from it), and every
  field is read as `r.target`, `r.points`, `r.t`… — inherited fields count, and a getter that throws escapes. Use the
  `rec` / `own` pair `motionread.ts` uses (own fields only, each read in a try), and read lists one index at a time
  (`listOf`) rather than `slice` / `map`.
- `readChain` iterates its whole input with `for…of`: a sparse array of length 2^32-1 that holds nothing readable
  takes about **57 seconds** (measured). Read at most `MAX_CHAIN * 4` indices.
- `readLane` keeps `-0` (`clamp(-0, 0, 4)` in `audiocore.ts` returns `-0`): `{ t: -0, v: -0 }` reads back as `-0`.
  `|| 0` after the clamp, as `motionread.ts`'s `num` does.

When done: move the five readers from the "audio library" block's `KNOWN` line into the hostile matrix of
`test/pro-review-safety.test.mjs` (add them to `readers()`), and that line goes.

## 2. Motion's import closure should not reach the sign-in screen (`MotionExport.tsx`, `Welcome.tsx`)

`MotionExport.tsx` imports `IS_MAC` from `Welcome.tsx`, which imports `SignIn.tsx`, which imports `account.ts`,
`gateway.ts` (both make requests) and `environment.ts` (which invokes `list_tree` and `read_file`). None of it is
called from Motion, so this is not a leak, but it puts two network modules and two file-reading commands inside what
"Motion makes no network request of its own" has to be checked against, for one boolean. Move `IS_MAC` to a module of
its own (for example `platform.ts`, re-exported from `Welcome.tsx` so nothing else changes) and import it from there.
Then remove `account.ts` and `gateway.ts` from `REACHED`, and `list_tree` / `read_file` from `PINNED`, in
`test/pro-review-safety.test.mjs` — the test will say so, since the found list must equal the pinned one.

## 3. The layer panel's fields should offer what the reader keeps (`MotionKinds.tsx`, `MotionLayers.tsx`)

The reader now holds a text layer's outline width to `textOutlineMax(size)` and its shadow's blur to
`textShadowMax(size)` (`motionread.ts`, R1-6 in the review): 2u and 6u for 3u words, the old 20u and 100u from 40u and
50u words up. The fields still offer `max={20}` (outline, `MotionKinds.tsx`) and `max={100}` (shadow blur,
`MotionLayers.tsx`), so on small words a value past the cap is typed, read, and shown back as the cap. For a text
layer, pass `max={textOutlineMax(layer.size)}` and `max={textShadowMax(layer.size)}` (both exported from
`motionread.ts`); other kinds keep 100 for the shadow.

## 5. `motiongifops.ts`: two readers of internal values (low)

`gifPlan(null)` throws (`o.side` of null; the default only covers `undefined`), and `gifSizeFor('__proto__', 720)`
is `{ width: NaN, height: 720 }` (`sizeOf` takes the prototype for a shape). Both are only ever called with values
the app made (`readPrefs` holds the GIF's side and rate to their lists, and a graphic's shape is read), so nothing
reaches them today. `o = {}` → `o ?? {}` inside, and `Object.prototype.hasOwnProperty.call(FORMATS, format)` in
`sizeOf` (`motiontypes.ts`) or in `gifSizeFor`.

## 6. The text-heavy frame (owner's decision)

With R1-6 in place, the heaviest frame a document can still ask for is sixty text layers of 500 letters split by
letter, each with an outline, a highlight box, a shadow and a shimmer: **0.33 s** a frame at 1080p and **0.57 s** at
4K in the app's WebKit (2.2 s and 7.2 s before). A gallery card (`MotionThumb.tsx`) paints one such frame per stored
graphic. If that is still too much, the next ceiling is a document-wide budget on letters drawn split
(`LIMITS.particleBudget`'s shape: earlier layers keep theirs), which would cut words a person wrote, so it is a
product decision rather than a reader repair.
