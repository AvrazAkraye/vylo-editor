# 05 Scenes and transitions: requests to the integrator

Things outside this package's files that it needs, in order of importance. Each says where and why.

## 1. Mount the strip (wave 2)

`app/src/MotionPanel.tsx`, in the full editor, directly above the timeline (today line ~947):

```tsx
<div className="mo-full-time">
  <MotionScenes t={t} doc={open} onEdit={onEdit} />
  <MotionTimeline t={t} doc={open} selected={sel} onSelect={select} onEdit={onEdit} />
</div>
```

`import { MotionScenes } from './MotionScenes';`. Props are `{ t, doc, onEdit, onSeek? }` — the studio's own
shapes (`t` the translator, `onEdit` from motionui.ts), not the brief's `{ doc, t: number, onChange, onSeek }`: in
this codebase `t` is always the translator, and every component edits through `onEdit(change, key)` so history
merges a slider drag into one step. The playhead is read from `motionplay.ts` as the timeline reads it; `onSeek`
defaults to its `seek`. The strip needs no space of its own until a graphic has two scenes (a single small
"+ Scene" button at the row's end). Whether it also belongs in the compact sidebar view is the integrator's call;
it works there unchanged.

## 2. Keep scenes through a template rebuild — `motionedit.ts`

`rebuild()` builds a fresh graphic from the recipe and drops every field it does not copy, so changing a
template's words, language, shape or length **loses the scenes** (split and transition edits keep the template
link on purpose). In `rebuild`:

```ts
const scenes = readScenes(m.scenes, fresh.layers, fresh.seconds);   // from './motionscene'
return { ...fresh, /* …what it copies today… */ ...(scenes ? { scenes } : {}) };
```

Only when defined, so a graphic without scenes stays without the key (`readMotion`'s fixed point needs that).
For a length change the scenes are re-read for the new length: those that no longer fit go.

## 3. Re-read scenes when the length changes by hand — `motionedit.ts` `setSeconds`

For a graphic edited by hand, `setSeconds` keeps `scenes` as they were. The renderer copes (it tidies the list on
every frame, so a scene past the end is simply not there) and `readMotion` repairs it on the next open, but until
then `doc.scenes` in memory can disagree with what is drawn. Re-read them the same way:
`readScenes(m.scenes, layers, s)`, set only when defined.

## 4. Put a new layer in the scene under the playhead — `motionedit.ts` `addLayer`, or its caller

`addLayer` makes a layer from 0 to the graphic's end. With scenes, that layer runs through every scene (it is
"the film's", see docs/pro/scenes.md). When the graphic has scenes, the caller should pass
`{ start, end } = sceneSpan(doc, read().t)` in the patch (MotionLayers.tsx's "Add layer", and the chat's add).

## 5. The chat's operations (wave 2) — `motionchatops.ts`, `motionai.ts`

Map onto the pure edits: `scene.add { at }` → `addScene`, `scene.split { at }` → `splitSceneAt`,
`scene.remove { scene }` → `removeScene`, `scene.move { scene, to }` → `moveScene`,
`scene.transition { scene, kind, d?, dir?, ease? }` → `setTransition`, `scene.rename { scene, name }` →
`renameScene`. A scene can be named by its id or by its 1-based number (`sceneList(doc)[n - 1]`). The model's
vocabulary for a whole document is in docs/pro/scenes.md ("The document"); `readScenes` accepts it loosely
(`"transition": "push"`, aliases, a missing `start`). The prompt should say: one primary transition for most cuts,
scenes carry no exits (the transition is the exit), at most 12 scenes of at least 0.5 s.

## 6. Known gaps elsewhere, for the review

- **Stage selection and hit-testing** (`MotionStage.tsx`) use each layer's live pose at the playhead. During a
  scene's hold before a transition, and during the transition, the picture shows the frozen moment, so the
  outline of a leaving layer can be off from what is drawn. A fix is to hit-test at the moment shown; the strip
  does not need it.
- **`stillTime`** (gallery card, cover) ignores scenes; it may land in a hold or a transition. Harmless, but a
  card of a scened graphic might prefer the first scene's still.
- **Sound (package 04)** may want a whoosh at each non-cut transition: `sceneList(doc)` gives each scene's
  `start` and `transition.d`.
- **Check (package 01)** could add tips: a transition longer than half a short scene, or a different transition
  at every cut (HyperFrames' "one primary transition" rule).
- **docs/MOTION.md** "Not in this version" and the limits paragraph should mention scenes (12, 0.5 s, 0.15–1.5 s).
