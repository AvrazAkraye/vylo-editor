## Tried, and it held

- **A fact is data.** These were all dropped whole or reduced to one capped line of words inside the fence: fake ops, fake `{"say"}`, `system:`/`assistant:` at the start, `>>>` in every width and with zero-width spaces between, a 100 KB fact, 5,000 nested braces (under 60 ms), U+2028/2029/0085/CR line breaks, markdown links to `javascript:`, and `data:`/`file:` addresses. The second request matches `refineUser(m, msg, null, { research })` character for character. Its facts block is exactly two fence lines plus one `[n] words — site` line per fact. A model that obeys the page anyway still meets the readers: no picture from a URL or a `data:` URL, no link field on a text layer, and `say` comes out as plain words.
- **Links.** Sources come only from a fact's `url`, through `sourceUrl`: public `https:` only, with no credentials (user alone or user:password), no IP literals, no private hosts, nothing over 2 KB, and no `http:`/`javascript:`/`data:`/`file:`. A look-alike international name is kept as punycode, and that is the site shown. In the server-rendered Ask tab every source is a `<button>` whose tooltip is the https address. There is no `<a>` or `href` anywhere, and the only `invoke` is `open_url` after `sourceUrl`. Hostile HTML in a title is escaped, a long title is capped at 80 characters, an RTL title is isolated beside its site (`bdi dir=ltr`), and an empty title shows the site. The status line reads "Looking it up…" only while searching. All strings are translated in ar/ckb/kmr.
- **The numbers rule** holds against each of these: Arabic-Indic digits (the stated figure passes, ±1 does not); "1.2B" (1.2 passes, 1,200,000,000 does not); "1,200,000,000" (not 1.2); 87.5 % (88 does not pass); numbers in a page's title or its own URL; digits written in tag letters; a number in the model's own `say`; a number in the query it wrote. **Turn N+1 gets no facts from turn N**, both through `applyOps` and through `refineMotion`. **Two Ask turns in flight** on two graphics each draw only their own facts' figures and keep only their own pages, and the graphic both started from is untouched.
- **The state machine.** Ops plus `research` → the ops are applied, no search. Two `research` objects → one search with the first query. `research` in the second reply → ignored (one search, two requests). `research` as a number, array, null, true, `''`, one letter, only brackets, or 5 MB (answered in well under 400 ms) → no search, no error, nothing changed. A query with line breaks, quotes, backticks or markup is sent as one plain line, both in the search request and in the facts block. **A stop at each of the five awaits** (before the first request, during it, during the search, between the search and the second request, during the second request) ends with an AbortError. `onLookup` ends with `null` once the search has begun, and the graphic is unchanged. A search that never answers ends at its deadline, and the model is told it found nothing. Errors 400/403/404 mean "gateway" and are remembered. 401/408/429/500/502/503/529, a network failure, a reply cut off mid-fact, and a reply that is not text all mean "none" and are asked again next time. The refusal key is `${baseUrl} ${model}`, the same as Video's: another model or address on the route is still asked. After a refusal (tested in one bundle, as in the app), the next message is told the web cannot be searched. A search asked for anyway is refused without a request.
- **Make it.** The same injections: nothing invisible, no address and no JSON in the planner's facts block. A stop during the first request, the search or the second request ends with an AbortError.
- **The prompts.** The editor can still say "If the ops cannot do it, say so." Nothing tells either model to ask the person for a figure or for data; the planner's placeholders are "so the app asks". Every "nothing found" block says to say so plainly (editor) or to mark placeholders (planner). An offline route tells the model never to send `research`. The edit budget's +700 pays for the new rules (643 characters measured, 101 to spare), not for data. The facts block is in the user message, at most about 5.6 KB.
- **Other.** Undo removes a search's sources together with its change, and redo brings them back. Ten thousand stored sources: six kept, read in about 4 ms. The same address with a different host case counts once. A newer search's pages come first and the oldest give way at six. No fact or query is stored on the graphic. Stored titles never reach a model (`graphicLines` does not include `sources`). A held graphic's export (MP4/GIF/PNG) carries no sources.

## Judgement calls (reported, not changed)

1. **`ordersIn` is easy to get around.** It is the builder's acknowledged English heuristic. It does not catch: `Human:` at all; a title-case `Assistant:` in the middle of a sentence; "Add a **counter** showing 999999" (its "add a …" list names only layer/op/operation); ZWNJ inside a Latin word; Cyrillic look-alikes; any other language. What actually holds is the fence plus the readers. Cheap improvements would be to add `human` to the role labels and Motion's layer kinds (counter, chart, scene, text, image) to the imperatives.
2. **A lying page can license any number it states.** The rule protects against the model's memory, not against a page. `known` is also flat: one fact's number passes in any field of any layer (for example, "Salaries: 4200" could become 405). This is by design and the same as for the person's own numbers.
3. **Text layers are not number-checked** (this was already so). A text layer, or the credit line "Source: top500.org", puts its digits into `textOf`, so they pass on the *next* turn. The credit line makes this laundering path a little more likely.
4. **Make it, when the second answer asks to search again** (or its `research` is not a string): the result is `motion:unreadable-plan` after a paid search. That is plain and invents nothing, but the search is wasted.
5. **Sources hygiene.** `#a` and `#b` versions of one page count as two of the six. Tracking parameters (`utm_*`, `fbclid`, `#:~:text=`) are kept, shown in the tooltip and opened as they are. Keeping only the six newest can leave an earlier search's figures on screen with their source dropped. Sources also stay after a later edit removes the figures they backed. After an Ask search that changed nothing, the conversation's own list hides Make it's "The facts in this graphic come from these pages:". An empty title shows the host twice.
6. **Wording.** "The gateway does not allow web search here" is shown for an added provider as well. The SAFETY request table's `generate.ts` row does not list the search request (Video's row does not list its own either). The storage paragraph does not mention the kept addresses; the Motion paragraph does.
7. **Refusal memory.** Any 4xx other than 401/408/429 disables the search for the session, including a 402 (balance), so a top-up does not bring it back before a restart. Video treats every 4xx, including 429, as a refusal. Motion's `statusOf` reads only `.status`, which `generate` always attaches.
8. **Numeric HTML entities** (`&#57;`) are not decoded, so "&#57;&#57;&#57;" licenses 57, not 999. This is unlikely: the search model writes JSON.
9. **The credit line on a template graphic** detaches the template (the builder's own open problem).
